# Implementation assumptions and manuscript issues

Source of truth: `demo_test.pdf` (manuscript, 2026-10-23) and the implementation brief
`CLAUDE_CODE_SIM_FAS_CF_MIMO_IMPLEMENTATION_SPEC.md`. Everything below is either **not specified** by the
manuscript (an assumption, configurable in YAML) or a **manuscript inconsistency** that the code resolves in
a stated way. Numbers in `configs/default.yaml` are illustrative development values, not paper results.

## 1. Assumptions (not fixed by the manuscript)

| Item | Implemented | Where / YAML key |
|---|---|---|

| CSI | Ideal, perfect AP-specific SIM-output-to-all-candidate-port CSI; no estimation, sounding or feedback overhead | `env.py` |
| AGA distances | 3-D distance from each feed (AP position + ULA offset, AP height) to the UE; stage-1 ties broken by (distance, l, u, k); stage 2 per Shi et al. Algorithm 1 (free feeds of an AP spread over its distance-ranked UEs) | `association.py` |

| Initial configuration of an episode | Equal power P_max/U per feed, uniform random phases, uniformly random port sets; the feedback (gamma, xi) of step -1 is that of this configuration | `env._draw_episode` |
| Episode end | After T = `env.episode_steps` steps: `terminated=True` (bootstrap 0), automatic reset with a new channel | `env.step` |

Centralized PPO/DDPG/TD3 actors also lose this input in those YAMLs | `env.global_state`, `config._blocks` |
| Actor observation | Eq.(28) contents; complex CSI as real/imag; the active ports of the controlled UEs as a K x Np 0/1 indicator plus a K-dim control mask (no port index 0 ambiguity); phases as cos/sin | `env.actor_obs` |
| Active-port sharing (`env.obs_ports_scope`, 2026-10-30, user's choice; default/bench_L6U2K4/bench_L6U2K4_perhead) | `served`: AP l sees the active ports of every UE it serves (>= 1 feed in F_l), i.e. the port choice of a UE is shared with all its serving APs (2 indices per UE); `controlled` (code default, original Eq. 27) = only the UEs whose FAS l controls. With `served` the port block no longer implies the control mask, so `env.obs_ctrl_mask` is back on; since 2026-10-31 `config.validate` rejects `served` with `obs_ctrl_mask: false` (the actor could not tell which of its port logits are applied) | `env.actor_obs`, `config.validate` |
| Local port gain and trunk freeze (2026-10-30, user's choice) | `ppo.fas_mode: strongest_local` (`mappo_spl`): the FAS-control AP picks the ports from its OWN contribution to the UE's stream (its CSI, its new phases and powers of step t), so no other AP's information and no UE measurement is needed; `strongest`/`strongest_new` (coherent over all serving APs) are kept and read as UE-measured port gains. `ppo.head_stop_freeze: true` (bench_L6U2K4_perhead): once a head's KL exceeds its threshold, the shared trunk and the stopped heads get no further update in that PPO update (gradients set to None so Adam momentum cannot move them); fixes the drift seen in perhead_6M. `ppo_sp`: centralized PPO with the `strongest` port rule | `phy.desired_port_power_local`, `OnPolicyTrainer.update` |
| Port-gain port baselines (`ppo.fas_mode`) | `strongest` (`mappo_sp`): each UE's n_k ports of largest desired-signal power through the configuration in effect (step t-1), applied with the new p, phase; `strongest_new` (`mappo_spn`, added 2026-10-30 at the user's request): the same rule through the NEW p, phase of step t, i.e. the UE measures its ports after the SIM is configured (an extra measurement phase per step). Ports are not learned in either | `mappo.trainer.to_env_action` |
| Per-head PPO update (2026-10-30, user's choice; `configs/bench_L6U2K4_perhead.yaml`) | `ppo.per_head_clip: true` (one ratio + clipped surrogate per head: power, phase, ports; cf. H-PPO, Fan et al. IJCAI 2019), `ppo.head_loss_weights: [1, 1, 1]` (weights of the three surrogates), `ppo.head_target_kl: [0.02, 0.02, 0.02]` (after an epoch whose mean KL of a head exceeds its threshold, that head leaves the loss for the rest of the update; the joint `target_kl` is off). Without `ppo.head_stop_freeze` the shared trunk is still updated by the remaining heads, so a stopped head can move slightly through the trunk (bench_L6U2K4_perhead sets `head_stop_freeze: true`). Per-head clipping drops PPO's joint-ratio monotonic-improvement argument (cf. HAPPO). `ppo.fas_stats_active_only` (2026-10-31, review M1; code default **false** = old behaviour, not enabled in any YAML: the user's decision): when true, the port-head surrogate, the FAS entropy bonus, `approx_kl_fas`, `clipfrac_fas` and the ports `head_target_kl` test are means over the agents with >= 1 active port draw only (power and phase stay plain means). With false, an agent controlling no UE (46.9% of the agents in the bench geometry) adds port ratio 1 and port KL 0 to the agent mean, so the ports threshold 0.02 only acts at ~0.038 per controlling agent | `OnPolicyTrainer.update`, `mappo.trainer.head_means` |
| Observation / state layout (2026-10-30, user's choice; `default.yaml`, `bench_L6U2K4.yaml`, `bench_L6U2K4_perhead.yaml`) | CSI = real/imag of Hbar x sqrt(P_max/sigma^2) only (`env.channel_encoding: raw_snr`); SIM phases as phi/2pi (`env.phase_encoding: raw`) in obs and state; actor obs WITH the FAS control mask (`env.obs_ctrl_mask: true`: it was off for a while on 2026-10-30, when the controlled-only port block implied it, and is back on together with `env.obs_ports_scope: served`, which requires it) and without xi (`env.obs_qos: false`, QoS/SINR only in the state); state without D (`env.state_distance: false`). Original-model run set (same day): no connection flags (`env.obs_conn_flag: false`), no post-SIM port gains (`env.port_gain_obs: false`), flat port head (`ppo.fas_head: flat`). Resulting sizes: bench_L6U2K4(_perhead) obs 3328 = [CSI 3200 \| F_l 8 \| p_l 2 \| phi_l/2pi 50 \| ports 64 \| ctrl 4], state 19632 (19633 before t/T was removed on 2026-11-04, as in the older archived runs); default.yaml (L=3, U=4) obs 3338, state 9882 (was 9883). `bench_L3U5K10.yaml` keeps the code-default layout (gain_direction, controlled ports, xi, connection flags, D, softmax power). Code defaults keep the old layout so older checkpoints load | `config._blocks`, `env.actor_obs`, `env.global_state` |
| CSI encoding | Lossless "gain_direction" encoding of every Hbar[l,k]: real/imag of Hbar / rms(Hbar), link SNR 10log10(rms^2 P_max/sigma^2)/10, per-port gain 10log10(\|Hbar_p\|^2 / mean_p)/10. Reason: the 30+ dB large-scale spread swamps per-feature standardisation of raw CSI (probe: MAPPO barely improved over its initialisation). `raw_snr` (Hbar x sqrt(P_max/sigma^2)) kept for ablation | `env.channel_features`, `env.channel_encoding` |
| Feature scaling | Channel blocks then standardised by per-feature running mean/std (training-only statistics, frozen at evaluation, stored with the model), clip +-10; powers / P_max; xi / R^min; log1p(gamma) clipped at 20; D / D_max | `env.py`, `utils.SliceNormalizer` |
| Random streams | The environment draws every random number (geometry, shadowing, fading, initial configuration) from a CPU generator and moves it to the device, so the scenarios are identical on CPU and CUDA | `utils.make_generator`, `env.py` |

| FAS entropy | Sum of the conditional entropies along the realised draw prefix (tractable surrogate) | `mappo/distributions.py` |
| Port order | The sampler produces an ordered sequence; PPO uses its likelihood (not the marginal probability of the unordered subset); the physical port set is order-free | `mappo/distributions.py` |
| Shared advantage | One centralized critic, one GAE per transition; every agent's PPO loss uses this common (minibatch-normalised) advantage; the loss is averaged over agents; the actor is parameter-shared by default (`ppo.shared_actor`). | Port-gain observation (`env.port_gain_obs`, on in bench_L6U2K4 from 2026-10-29; **superseded 2026-10-30**: off again in every YAML, `port_gain_obs: false`, user: original model, ports learned from the obs only) | Per UE, the desired-signal power at every candidate port through the CURRENT SIM phases and powers, coherently summed over its serving APs (what the UE can measure per port from downlink pilots and feed back to its port-controlling AP): Np gains relative to their mean + 1 level vs noise, dB/10. | Baselines | PPO = one centralized agent on the global state (same heads, same critic). ## 2. Manuscript issues found while implementing

| # | Issue | Resolution in the code |
|---|---|---|
| 1 | Eq.(23): quantifiers `forall p, j` on both sums; should be column sums = 1 `forall j`, row sums <= 1 `forall p` | Distinct active ports enforced (`fas.validate_ports`) |
| 2 | Eq.(11)/(24f)/(25): `forall l, u, k` on scalar sums | sum_k F = 1 for every feed (l, u); sum_{l,u} F >= 1 for every UE k (`association.check_association`) |
| 3 | Eq.(10)-(12): the column of F_l is called both e_{l,k} and f_{l,k} | `F[l, :, k]` |
| 4 | "This association requires LU >= K for feasibility": LU >= K guarantees coverage only, not rate feasibility | Validation error if LU < K; QoS treated as soft (penalised P2), satisfaction reported separately |
| 5 | Power map Eq.(28)-(29) (softplus + rescale) in demo_test.pdf vs. U+1 softmax in the revised text | **U+1 softmax with an unused share** (revised manuscript, decided by the user). 2026-10-29: the user switched the benchmark to `env.power_map: linear` (adapted from their SIM/PPO reference code): p_lu = P_max (a_lu + 1)/2 per feed, a in [-1, 1], scaled down to P_max when the AP's sum exceeds it; unused power still allowed, reward unchanged (`bench_L6U2K4.yaml`, `default.yaml`; `softmax` stays the code default for old models). The manuscript's power map must describe whichever map the reported results use |
| 6 | Reward equation duplicated / referenced as (24a) in places | r_t = sum_k R_k - lambda_QoS sum_k [R_k^min - R_k]^+ |
| 7 | Eq.(2) uses r_{k,p} while Eq.(1) defines q_n for the port positions; Q is used for SIM matrices, the active-port set and positions | Code names: `Q1`, `Qinter` (SIM), `ports` (active set), `port_coordinates` |
| 8 | Section III-D (Q-PPO) is empty | Not implemented; no quantum method is invented |
| 9 | T_l = B_l Q_{l,1} is said to map to the "input" SIM layer; it maps the feeds to the output layer | `sim_apply(phase, Qinter, Q1)` = B_l Q1 |

## 3. Things the results do NOT show
- No CSI-acquisition or port-sounding overhead is modelled; SE values are ideal.
- The QoS penalty is finite: R_k >= R_k^min is not guaranteed (see `final_qos_all`, `final_shortfall`).
- Nothing here proves convergence or optimality of any learner; the training objective (discounted sum over
  the T refinement steps) is a surrogate of the per-realisation problem (P2).
